# 工具页 MCP 分类设计

**日期：** 2026-09-03

## 目标

让工具页把 MCP 工具从普通工具中明确区分出来，并提供「元工具 / MCP / 常规工具」三类筛选，同时保持现有批量启停和原地更新行为。

## 分类规则

分类由工具数据统一派生，不新增后端字段：

1. `mcp_source` 非空：`MCP`
2. 否则 `meta === true`：`元工具`
3. 其他情况：`常规工具`

分类优先级为 MCP > 元工具 > 常规工具，保证展示标签和筛选条件互斥。MCP 工具继续使用后端已有的 `mcp_source` 字段；普通工具和元工具的现有数据契约不变。

## 页面行为

- 类别标签显示为「MCP」「元工具」「常规工具」，三者使用不同视觉语义。
- 筛选栏调整为「全部 / 元工具 / MCP / 常规工具」。
- 切换类别筛选时清空当前选择，避免对被隐藏的工具执行批量操作。
- 工具开关、批量启停、请求失败保留原状态的行为保持不变。
- MCP 工具仍可以在工具页测试、启停和删除；MCP 服务源的注册/删除继续由 MCP 页面负责。

## 实现与测试

- 在前端增加单一分类派生函数，类别筛选和表格标签共用，避免两处条件漂移。
- 为分类函数增加覆盖 MCP、元工具、常规工具以及 MCP 与 `meta` 同时存在时优先级的单元测试。
- 更新工具页组件测试和 mock E2E，验证三类标签、三类筛选和 MCP 工具不会出现在常规工具筛选中。
