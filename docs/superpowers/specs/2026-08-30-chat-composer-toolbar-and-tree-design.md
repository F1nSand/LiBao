# 对话框工具栏与文件树可用性优化设计

## 背景

Chat 与 Workspace 的输入区已经完成卡片化和控件尺寸统一，但当前工具仍与文本输入同一行排列，导致输入区的视觉重点不够明确；Workspace 的上传、引用、模型与发送控件也没有形成清晰的左右分组。文件树在文件名较长时，行尾更多操作入口可能被名称挤出可视区域，影响重命名、删除等操作。

## 目标

- Chat 与 Workspace 的输入框独占上方，底部工具栏承担全部操作。
- 工具栏左侧从左到右为“+ 添加文件”；Workspace 额外显示浅色分隔符“|”和“引用”。
- 工具栏右侧从左到右为“切换模型”和“发送/中断”，发送/中断始终贴近右侧。
- 工具按钮去除持久边框，普通工具仅在 hover 时显示浅色背景；发送/中断保留语义色背景但不显示边框。
- 移除 composer 右下角的字符计数提示；输入长度限制仍由 textarea 的 `maxlength` 和发送校验负责。
- `+` 继续复用现有附件上传能力，仅改变入口图标和位置，不新增应用选择或其他业务菜单。
- 文件树名称超长时显示省略号，右侧更多操作保留固定宽度、可见命中区和键盘入口。
- 保持桌面端紧凑、移动端 44px 触控命中区，以及既有拖拽上传、引用、模型、发送和中断逻辑。

## 非目标

- 不新增应用选择、附件类型或菜单业务。
- 不改发送、停止、上传、引用、模型加载或模型切换逻辑。
- 不改 API、mock、路由、数据模型、后端契约或文件树数据同步逻辑。
- 不引入新的 UI 依赖、图片资源或新的全局设计令牌。

## 设计决定

### Composer 结构

每个 composer 保留现有附件/引用 chip 行，并将主体拆成两层：

1. `composer-textarea`：位于上方，横向占满可用空间。
2. `composer-toolbar`：位于下方，使用 `space-between` 分成左右两组。

左组继续使用 `.composer-leading`：Chat 只包含上传入口；Workspace 按 `+`、`|`、`引用` 顺序包含三个元素。右组继续使用 `.composer-actions`：按模型按钮、发送或停止按钮顺序排列，不插入分隔符。

### 按钮语言

- 上传入口由纸夹图标改为 `+`，无文字，`aria-label` 与提示文案为“添加文件”，仍支持点击、拖拽和键盘 Enter/Space。
- 普通上传、引用、模型按钮使用透明背景和无边框；hover 使用项目浅边框色背景，focus-visible 使用清晰焦点环。
- 发送按钮使用主色实心背景，停止按钮使用危险色浅背景；二者均无边框，并保持 loading/disabled 状态。
- 桌面控件高度保持 36px，移动端提升/保持为 44px；工具栏在 768px 以下仍不产生页面横向溢出。

### 文件树

文件树节点行和名称均允许收缩，名称使用 `min-width: 0`、单行省略；更多操作所在的 Element Dropdown 根节点与按钮共同形成固定宽度的操作栏。操作按钮采用固定 28px 桌面命中区，使用无边框透明背景，hover 显示浅色背景，focus-visible 可见；长名称不能改变其位置或遮挡它。

## 验证标准

1. Chat 与 Workspace 的 `.composer-input` 子结构均为 textarea 在前、toolbar 在后。
2. Workspace 左组顺序为上传入口、分隔符、引用；右组顺序为模型、发送/停止；Chat 左组仅为上传入口。
3. 普通 composer 工具的 computed `border-style` 为 `none`，发送/停止同样无边框；hover 能读取到非透明背景。
4. 390×844 下 composer 不横向溢出，工具按钮高度至少 44px；输入区仍可完成添加文件、引用、切换模型、发送/中断。
5. 创建超长名称文件后，文件名节点发生省略，更多操作按钮及其固定命中区仍位于树行可视范围内并可打开菜单。
6. 既有上传、引用、模型、发送、停止、文件树菜单与数据同步测试不回归。
