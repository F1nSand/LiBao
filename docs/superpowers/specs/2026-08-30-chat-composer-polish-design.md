# 聊天输入区视觉优化设计

## 背景

聊天页与工作区页的 composer 当前使用顶部边框承载输入区，上传标签、Element Plus 按钮和模型选择按钮的高度、圆角与视觉层级不一致。输入区功能已经稳定，本次只改善可读性、层次和操作反馈。

## 目标

- 将输入区呈现为轻量的现代编辑器卡片，和内容区保持协调。
- 统一上传、引用、模型选择、发送/停止控件的高度、圆角、间距和交互反馈。
- 文本输入更宽松，默认无多余内框，聚焦时由 composer 提供清晰的焦点提示。
- Chat 与 Workspace 使用一致的视觉语言；保留 Workspace 的附件与文件引用 chip。
- 桌面端保留已选模型名称，窄屏仍保持可用的折叠标签。
- 移动端交互命中区不小于 44px，页面不产生横向溢出。

## 非目标

- 不改发送、停止、上传、引用、模型加载或模型切换逻辑。
- 不改 API、mock、路由、数据模型或后端契约。
- 不引入新的 UI 依赖或图片资源。

## 设计决定

### 容器

将 Chat 与 Workspace 的 `.composer` 从单独的顶部边框改为带 1px 边框、较大圆角和轻阴影的卡片。桌面端与内容边缘保留呼吸空间；移动端缩小外边距和内边距。`focus-within` 使用 indigo 的低强度外环，拖拽中使用同一主色的浅背景与边框强调。

### 输入与控件

- textarea 使用透明背景、无 Element 默认内框，增加水平/垂直留白；高度随 autosize 保持现有行为。
- 桌面端所有 composer 控件统一为 36px 高；按钮圆角统一为 10px，内部图标与文字垂直居中。
- 上传控件继续使用自绘 `label.upload-btn`，但纳入 composer 的统一边界、hover、focus-visible 和尺寸规则。
- 模型按钮保留模型名称并限制最大宽度；引用按钮保留“引用”文字；发送为主色按钮，停止为危险色按钮。二者统一高度与圆角。
- chip 维持现有功能，调整到与卡片间距一致的间隔。

### 响应式与无障碍

- 768px 以下仍采用 textarea 独占一行、下方左右操作区的布局。
- 手机端控件最小高度保持/提升到 44px，并保留现有无横向溢出约束。
- 不移除原生焦点轮廓；对自绘上传标签补充 `:focus-visible` 样式。
- 过渡使用现有 `--ease-out`，增加 reduced-motion 覆盖。

## 验证标准

1. Chat 与 Workspace composer 的桌面控件高度一致，textarea 默认无明显 Element 内框。
2. composer 聚焦、hover、拖拽、禁用状态均有可辨识反馈。
3. 390px 手机视口下，composer 的宽度不溢出，操作区仍位于 textarea 下方，控件命中区至少 44px。
4. 现有发送、停止、上传、引用、模型选择交互与测试不回归。
